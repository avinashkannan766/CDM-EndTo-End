# Study Specification — DM-001

## 1. Study Overview

- **Study ID:** DM-001
- **Study Title:** A Simulated Clinical Study of Drug X in Adults with Type 2 Diabetes
- **Project Type:** Educational Clinical Data Management (CDM) portfolio project
- **Study Design:** Randomized, parallel-group, two-arm simulation
- **Study Duration:** 12 weeks per participant
- **Planned Participants:** 30 fictional participants
- **Study Status:** Study setup

> **Disclaimer:** This is a fictional training study using synthetic data. It is not a real clinical trial or a validated medical protocol.

## 2. Study Objective

To simulate the clinical data management workflow for a fictional 12-week study comparing Drug X with placebo in adults with type 2 diabetes.

The project will demonstrate study documentation, CRF design, data entry, edit checks, query management, data review, reconciliation, and database-lock readiness.

## 3. Study Design

- **Population:** Fictional adults aged 18–70 years with type 2 diabetes.
- **Treatment Arms:**
  - Arm A: Fictional investigational Drug X
  - Arm B: Matching placebo
- **Allocation:** 1:1 randomized allocation in the simulated dataset.
- **Visit Schedule:** Screening, Baseline, Week 4, Week 8, and Week 12.
- **Data Domains:** Participant demographics, eligibility, informed consent, medical history, concomitant medications, vital signs, laboratory results, adverse events, and visit completion.

## 4. Data Management Scope

The simulated CDM workflow will include:

1. Study setup and documentation.
2. CRF structure and data dictionary development.
3. Edit-check specification and implementation.
4. Simulated CRF data entry and form-completion tracking.
5. Data review and query generation.
6. Query assignment, response, and resolution tracking.
7. Missing-data and cross-form consistency review.
8. Reconciliation and outstanding-issue review.
9. Database-lock readiness checklist and final cleaning summary.

## 5. Data Quality Principles

- Preserve the original raw dataset.
- Record corrections transparently.
- Distinguish errors requiring correction from review flags requiring assessment.
- Track every query through an explicit status.
- Maintain traceability between findings, queries, and resolutions.
- Use only fictional participant information and synthetic clinical data.

## 6. Planned Deliverables

- Study specification
- CRF design specification
- Data dictionary
- Edit-check specification
- Synthetic CRF dataset
- Data query log
- Form completion tracker
- Data review and reconciliation reports
- Database-lock readiness checklist
- Final project README and documented test results

## 7. Limitations

This project is an educational simulation. It does not demonstrate work on a real clinical trial, production electronic data capture (EDC) system, or actual database lock. The fictional study design and checks are for portfolio demonstration and are not intended for clinical decision-making.
